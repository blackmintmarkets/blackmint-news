Anza Urges Solana Validators to Install Agave v4.4.2 Right Away

The patch updates the QUIC networking code validators use to talk to each other. Anza said Solana's clusters were running normally.

Anza, the company that develops Solana's Agave validator software, told mainnet node operators on Friday, Nov. 27, to install Agave v4.4.2 immediately. "Don't wait, upgrade now," Anza posted on X at 6:31 p.m. ET, adding that "clusters are safe and running normally."

The alert covers every Agave-based node, staked or unstaked. Operators on Solana's testnet and devnet were told to move to v4.5.0-rc.1, a release candidate published on GitHub the same day.

What the patch changes

Validators are the computers that check transactions and produce blocks on Solana. They take in transactions over QUIC, an internet transport protocol, according to Anza's documentation. Agave ships its own copy of quinn, an open-source Rust library that implements QUIC.

The v4.4.2 release notes, posted at 2:04 p.m. ET, list a bump of those "anza-quinn" crates as the main change. The pull request says the crates "need a fix backported from upstream quinn." That upstream fix, quinn pull request 3030, is titled "handle large number of unacked packets." Unacked packets are pieces of data a computer has sent but the other side has not yet confirmed receiving.

Anza's backport, merged at 11:31 a.m. ET, says the upstream pull request was still open. Anza said nothing else changes in v4.4.2 "beyond small backports," in a follow-up post. It did not publicly describe what could happen to a node that skips the update.

Other clients follow

Jito-Solana and Harmonic, two validator clients built on Agave code, released their own v4.4.2-based versions, Anza said. The Defiant also reported both releases. Solana co-founder Anatoly Yakovenko shared the alert on X with the words "Upgrade pls!!!"

In our opinion: The bigger story is the speed. Anza's backport and the mainnet release landed about two and a half hours apart on the Friday after Thanksgiving, for a fix that was still under review in the upstream library. Operators are patching on the strength of the warning alone, because Anza has not said what an unpatched node risks. The next thing to watch is whether Anza publishes a fuller explanation once the upgrade has spread across the network.
